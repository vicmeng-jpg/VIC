# 實戰專案：自動化船員評估試題爬蟲開發心得
**日期：2026-04-10**

這兩天我著手整理並開發了一個「船員評估試題智慧批次爬蟲系統」。這個實戰專案不僅讓我更熟悉 Python 的網路爬蟲技術，更重要的是，我學到了許多在「真實世界資料」中會遇到的各種不規則狀況。以下是這次開發過程中，我認為最具價值的幾項技術心得。

## 1. 原來歷史資料這麼亂：字串正規化 (Text Normalization)

剛開始寫爬蟲時，我以為只要找出科目名稱，直接比對字串就好。但當程式實際爬梳了幾十個歷史梯次後，我才發現官方網站的命名非常不統一。有些會有全形括號，有些有空白，甚至還有「新制」、「舊制」等干擾字眼。

為了解決這個問題，我寫了一個 `normalize_text` 函數：
```python
def normalize_text(text):
    """正規化字串，去除不必要的空白、括號、以及新舊制等干擾文字，並統一注音一與國字一"""
    if not text: return ""
    t = text.replace(" ", "").replace("\n", "").replace("\r", "").replace("\t", "").replace("\xa0", "").replace("　", "")
    t = t.replace("◎", "").replace("新制", "").replace("舊制", "").replace("(", "").replace(")", "").replace("（", "").replace("）", "")
    t = t.replace("ㄧ", "一") # 注音的 ㄧ 換成國字的 一
    return t.strip()
```
這讓我體會到，網路爬蟲最花時間的往往不是連線發送請求，而是如何優雅地清理與對齊「髒資料 (Dirty Data)」。

## 2. 避免重複下載的「預先檢查」機制

在處理大量批次下載任務時，如果中途斷線，重新執行爬蟲時又從頭下載一次，會非常浪費網路資源與時間。所以我加入了 `glob` 套件，在實際發出 Request 之前，先掃描本地端目錄是否已經存在相同名字的檔案。

```python
existing_files = glob.glob(f"{expected_prefix}.*")
if existing_files:
    print(f"    [略過] ... (資料夾下已有先前下載資料，不重複下載)")
```
這個小小的防呆機制，大幅提升了爬蟲的執行效率與友善度。

## 3. 網頁結構防呆處理

很多時候，PDF 下載連結並不一定會有清楚的文字標示。有時候是直接掛在一個副檔名為 `*.pdf` 或 `*.xlsx` 的 `<a>` 標籤上，有時候文字則是統一寫著「下載」。如果單純只抓 `<a>` 標籤裡面的文字，很容易抓不到正確的科目名稱。

為了處理這個問題，我學會往上尋找父節點（Parent Node）：
```python
tr = a.find_parent('tr')
# 取得整行文字，然後去掉多餘空白和"下載"字樣
text = tr.get_text(" ", strip=True).replace("下載", "").strip()
```
這種動態向上解析的方法，可以適應大部分老舊網站不穩定的 HTML 表格結構。
